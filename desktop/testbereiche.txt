# Testbereiche (AP-132): Welche Tests der PR-Check für welche geänderten Dateien laufen lässt.
#
#   ./gradlew -p desktop testAuswahl                      # Tests zu den Änderungen gegenüber origin/main (auch nicht eingecheckte)
#   ./gradlew -p desktop testAuswahl -Pseit=HEAD^1        # gegenüber einem bestimmten Stand (so im PR-Check)
#   ./gradlew -p desktop testAuswahl -Pbereiche=video,pdf # bestimmte Bereiche (dazu immer „kern“)
#   ./gradlew -p desktop testAuswahl -Pzeigen             # nur anzeigen, was liefe
#
# Aufbau: [name] Beschreibung, darunter „quellen:“ (Dateimuster) und „tests:“ (Namen von Testklassen, * erlaubt).
# Muster mit / am Anfang gelten ab dem Repository, alle anderen ab dem Paket io/github/thepytales/llmhub/ in
# app/src/main/java und desktop/src/main/kotlin. * steht für beliebige Zeichen ohne /, ** auch über Ordner hinweg.
#
# Regeln (testbereiche.gradle.kts):
#  - Eine Datei aus [doku] braucht keine Tests, eine aus [android] nur den Android-Build (gemeinsame Dateien, die die
#    Windows-Version durch eine eigene ersetzt, erkennt die Auswahl selbst).
#  - Eine Datei aus [alles] – und jede Datei, die zu keinem Bereich passt – lässt die volle Sammlung laufen. Ebenso eine
#    Datei, die mindestens 15 Testklassen direkt benutzen (z. B. AppContainer, SettingsStore): sie betrifft fast alles.
#  - Sonst laufen die Tests aller Bereiche, zu denen die Datei passt, dazu jede Testklasse, die eine Klasse der Datei
#    direkt benutzt (aus dem kompilierten Code gelesen), und immer die Tests aus [kern].
#  - Eine geänderte Testdatei lässt ihre eigenen Tests laufen und alle, die sie benutzen (z. B. CommandCorpus).
#  - Testklassen, die in keinem Bereich stehen, gehören zu [kern] und laufen immer – neue Tests gehen so nie verloren.
#  - Vor jedem Release und einmal pro Woche läuft ohnehin die volle Sammlung (README › PR-Check).
